## Summary

Migrate accepted scenario capability groups to Inspect through frozen dual execution, independently verified parity, and deliberate removal of only the runner responsibilities that Inspect replaces.

## Context

Migration proceeds by capability: read-only review, simple mutation, offline dependencies, governed blocking, multi-agent orchestration, claim and Git lifecycle, then exceptional browser and runtime facilities. Specialized current-runner lanes may remain when that produces the safer and simpler architecture.

Estimated complexity is Very High. Estimated generation is 400,000–800,000 tokens, or 2.22–4.44 total agent-hours, across 25–45 turns. Non-model runtime depends on measured live-suite execution and must be budgeted separately.

## Source Evidence

The user authorized the phased Inspect-first adoption series on 2026-08-12. This item implements Phase 8 of that proposal.

## Requirements

- Define migration waves from the accepted capability routing table.
- Freeze each scenario during dual execution.
- Compare governed status, every deterministic disposition, identity, evidence, mutation, containment, and cleanup.
- Measure generated tokens, total agent-hours, critical-path agent-hours, turns, non-model runtime, and maintenance effort per scenario.
- Remove current runner code only after its complete responsibility has direct replacement evidence.
- Preserve explicit retained lanes and document why they remain.
- Produce a final adoption decision and steady-state maintenance contract.

## Acceptance Criteria

- Every migrated scenario has independently accepted parity evidence.
- No migrated result weakens a critical gate or semantic status.
- The final architecture removes a material, measured portion of current maintenance.
- Adding and maintaining representative scenarios consumes fewer agent-hours.
- One acceptance authority remains across Inspect and retained lanes.
- Final documentation states migrated, retained, deprecated, and removed surfaces precisely.

## Dependencies

generate-inspect-ai-evaluation-catalog. Unblock when generated Inspect definitions and stale-output enforcement are accepted.

## Verification

- Execute each wave through both harnesses with the repetition count justified by measured variability.
- Perform independent verification before removing any current code.
- Run focused integration, catalog, report, evidence, containment, and cleanup checks after each wave.
- Complete a final architecture and artifact review.
