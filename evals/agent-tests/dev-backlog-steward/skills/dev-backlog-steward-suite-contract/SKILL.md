# Dev Backlog Steward Suite Contract

Evaluate ordinary durable typed lifecycle state through the effective Persistence-selected backend, while routing explicitly requested lightweight Future Ideas only through the file provider or an explicit one-item file override. A Future Idea has a title, Synopsis, Origin or Rationale, optional Notes or Revisit Trigger, no lifecycle fields, and the output contract backlog item, Future Idea, or status update. A non-file Future Idea operation without the override is BLOCKED and creates neither a provider issue nor a shadow file. Explicit inventory and validation read only canonical regular files, report every invalid, duplicate, unreadable, or authority-escaping entry without reading external bytes, keep Future Ideas separate from ordinary lifecycle counts, and perform no mutation. Promotion preserves the idea with Promoted To and creates complete ordinary work whose Source Evidence contains the exact idea path, whose Completion is direct-main, feature-branch, or UNSET, and whose Open Questions section records agent-resolvable uncertainty or None. The peer commit-file-provider-transaction skill owns promotion mutation and recovery mechanics; the Steward supplies validated reciprocal records and preserves its result. Evaluate that transaction as failure-atomic: preflight target collisions; snapshot exact manifest path state, HEAD, exact full Git index file bytes and existence, and unrelated staged and dirty state before coordination; acquire both exact source and destination path claims when agent-claim applies; revalidate every snapshot after claims and before mutation; return zero-mutation BLOCKED on drift; create the target without overwrite; stage only the reciprocal pair; use a path-limited commit that preserves unrelated state; capture the new commit OID; and verify that captured immutable commit OID contains exactly both paths and reciprocal bytes. After a target-write, idea-write, validation, staging, or commit failure, the peer transaction restores and verifies the exact worktree and Git index snapshots. Restoration removes only a target created by that promotion attempt. When resource_coordination selects agent-claim, release both path claims after success, a zero-mutation drift stop, or safe verified rollback, and retain both after unsafe rollback or post-commit reciprocal verification failure. An existing target blocks promotion. When resource_coordination selects none, make no claim discovery, call, registry mutation, release, or claim evidence while performing the same immediate pre-mutation revalidation. In either mode, unsafe recovery reports BLOCKED and names the preserved evidence and Dev Backlog Steward recovery owner. Holding accepts the underlying dispatchable Type or Type: Holding; User Action Required retains its underlying dispatchable Type. Directly requested or explicitly authorized ordinary items start Ready in their typed active queue. Status: Proposed is invalid. Ordinary items need source context, requirements, acceptance, dependencies, and verification; claimed or resumed items need visible exclusive ownership. Recovery must reconcile item, claim, logs, results, and verification before completion or archival. A blocked handoff commits Status: Blocked, Owner: Unowned, and Claim: None while retaining the exact blocker, unblock condition, evidence, and acceptance criteria, then releases prior ownership so both item and registry are unowned. Reject an unowned Blocked to Running shortcut even when the unblock condition is satisfied. Resumption records eligible Ready state, successful acquisition of a new claim, the new owner, and only then Running. A failed or absent claim must restore the exact pre-attempt Blocked bytes, keep the item unowned and not Running, and preserve all prior evidence. Reject GitHub issues for Future Ideas, shadow backlogs, state-implied ownership, unsupported status changes, lost history, or unrecoverable handoffs. Judge item or idea quality, ownership integrity, transition evidence, promotion provenance, recovery, evidence preservation, output completeness, and handoff completeness.

For promotion identity, require Promoted To to equal the destination Work Item ID, require that
Work Item ID to equal the destination filename stem, and require reciprocal Source Evidence with
the exact retained idea path. Model source and destination coordination as one atomic acquire
operation containing both exact paths. A conflict on either path acquires nothing, retains no new
ownership, and returns zero-mutation BLOCKED before post-claim revalidation or repository mutation.
