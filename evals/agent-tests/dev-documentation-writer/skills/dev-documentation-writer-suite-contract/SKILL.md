# Dev Documentation Writer Suite Contract

Evaluate source-backed non-wiki documentation through exactly one applicable methodology or custom-page route. Require authoritative evidence, steady-state language, the route-specific artifact contract, explicit unresolved conflicts and gaps, truthful verification, and a clean commit and claim closeout. Preserve established README or custom-document format. Do not accept mixed templates, invented behavior, or a completeness claim for bounded or evidence-incomplete reverse engineering.

For a template-owned module design, require the target to load the canonical module design template before drafting and to preserve every top-level level-two heading exactly once in template order. Visible nested blockquotes remain evidence-bearing prose, while fenced content and HTML comments do not satisfy headings, readiness, source references, or test-evidence claims. Require the first visible Implementation Readiness content to begin with READY. or BLOCKED., either plain or with balanced canonical Markdown emphasis, and to agree with the evidence-backed contract state. Put every runnable verification command in exactly one command-only bash, sh, or shell fenced block so the deterministic command inventory can compare every complete command line with the fixture allowlist. Inventory direct launchers, command directives, inline commands, Node commands, and bounded environment or process wrappers without treating explanatory tool prose as a command. Resolve inline and reference-style source and test destinations relative to the documentation artifact, require the contract-owned fixture output path, and ignore unrelated external references rather than treating them as local evidence. Run the fixture-native final validator before semantic judgment. Treat a canonical-template digest mismatch, heading mismatch, invalid readiness lead, unresolved template TODO, escaping or nonexistent source or test reference, malformed command block, unapproved verification command, or visible contradictory automated-coverage claim including anaphoric restatements as a critical deterministic failure. First-attempt conformance means the committed artifact passes these gates before reviewer or Judge correction; later repair does not satisfy the scenario.

Judge route correctness, source traceability, canonical structure, readiness integrity, test-evidence fidelity, artifact usefulness, verification integrity, and closeout.
