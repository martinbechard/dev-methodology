# Project Configurator Suite Contract

Evaluate one disposable synthetic project fixture and its reviewable PROJECT.yaml or proposed invalid configuration. The supervisor must copy the selected executableCase directory to a fresh Git repository and give the target that repository root; the dev-methodology checkout is evidence only and is never the configuration target. Treat runtimeCapabilities as exceptional process and network facilities, not as the available-skill catalog. The targetSkills whose staged SKILL.md files are verified before dispatch are the runtime-exposed skill catalog for the scenario.

Require source-backed representative folder detection, comparison with runtime-exposed technology skills, explicit NO_VARIANT for pertinent unsupported scopes, BLOCKED for required unavailable skills, valid conceptual definitions, mutation and claim consistency, and root or nested AGENTS.md plus Claude bridges where evidence requires them. Generic claim procedure text must not be copied into project guidance. Judge evidence quality, routing precision, capability validation, reference integrity, protected-input integrity, fixture cleanup, and closeout.

## Valid Configuration Reuse

Apply this section only when the selected scenario id is valid-configuration-reuse. Do not apply its preservation gates or authority packet to technology-routing or invalid-configuration.

Freeze TASK.md and README.md as the authority for the worker-old to worker move. Freeze README.md, TASK.md, available-skills.txt, worker/main.py, and worker/test_main.py by digest and require them to remain byte-for-byte unchanged. Treat the existing PROJECT.yaml, root guidance, nested guidance, and Claude bridges as a reusable configuration baseline: change only statements and paths made stale by the authoritative move, while preserving still-supported intent.

Preserve the complete technology_skill_loadouts sourceEvidence structure. Each sourceEvidence value remains a list of mapping rows, and each row retains its skill, runtimeAvailability, and evidence fields. Each row's evidence field remains a list whose elements are scalar strings. For this fixture, the worker move does not make the sourceEvidence subtree stale because it already names worker/main.py, so require that complete subtree to remain semantically equal to the frozen baseline. A bare scalar path is never a valid sourceEvidence row.

Require generated AGENTS.md text and any changed PROJECT.yaml evidence or fact statement to use plain source-faithful language supported by frozen fixture authority. A valid path update is not evidence that unrelated behavior, ownership, runtime, privacy, or verification facts changed.

## Technology Routing

Apply this section only when the selected scenario id is technology-routing. Treat the fixture's anchored /.worktrees/ ignore rule as a frozen setup prerequisite, not as target output. Verify the rule before dispatch and require it to remain unchanged. Do not apply valid-configuration-reuse move provenance, baseline-preservation, or changed-statement gates to this scenario.

Freeze and supply the complete canonical project template and the complete canonical Project Configurator conceptual definition. Require PROJECT.yaml to retain schema project, schema_version 1, and every mandatory section in the canonical project template. Derive the canonical fixed and conditional skill sets from the supplied definition. Require role_agent_set to select that definition with every fixed skill fixed, every conditional skill conditional with its canonical condition, and no missing, duplicated, added, or reclassified skill. For the frozen source, detect-technology-skills, create-project-configuration, route-documentation-work, and verify-documentation-page are fixed; bootstrap-project-documentation is conditional.

Require exactly four Claude bridges at CLAUDE.md, service/CLAUDE.md, ui/CLAUDE.md, and infra/CLAUDE.md. Each bridge must contain exactly the functional import line @AGENTS.md followed by one newline and no other content. Check file bytes rather than accepting a target summary, PROJECT.yaml declaration, descriptive prose, a mention of AGENTS.md, or existence alone. Reject a missing or extra bridge, alternate import target, duplicated import, heading, explanation, or trailing content.

Mutation agreement is applicable because the supplied definition declares required repository mutation. Require a passing source-faithful mutation agreement and validate resource-claim separately as the project-selected resource-coordination procedure. The deterministic packet and Judge packet must identify the canonical project template digest, mandatory section comparison, conceptual definition evidence, exact fixed and conditional skill comparison, per-bridge path and byte comparison, mutation agreement result, and separate resource-claim disposition.

## Invalid Configuration

Apply this section only when the selected scenario id is invalid-configuration. Bind one exact CANDIDATE_REPOSITORY_ROOT marker to a fresh candidate below the runner-owned active scenario root. Require direct repository inspection of PROJECT.yaml, proposed-role.yaml, and available-skills.txt before the target returns BLOCKED. The shared evidence boundary requires one separate literal read of each file, its uniquely paired well-formed output after the call and before the verdict, exact complete frozen contents, the bound candidate workdir, and explicit forwarding of the nested command output. Any missing, duplicate, dynamic, spread, multi-call, additional-tool, multi-file, wrong-root, malformed-output, post-verdict, or contaminating attempt fails the runner-owned paired pre-verdict receipt audit.

Require target-owned path-and-field observations for repositoryMutation, definition skills, the required technology skill, runtimeAvailability, routing status, and catalog presence. Supervisor assertions and independent deterministic checks corroborate those observations but cannot replace them. Reject repetition of supervisor findings, supplied conclusions, or fixture summaries when the target supplies no direct repository inspection evidence. Keep the runner audit as infrastructure evidence; do not add a scenario or catalog check named runner-owned-repository-read-receipts.
