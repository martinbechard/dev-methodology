# Dev Backlog Coordinator Suite Contract

Evaluate the parent coordinator rather than a per-item Dev Orchestrator or provider manager. Require the target to identify itself as Dev Backlog Coordinator, use the separate codex-workitem-coordination skill, obtain durable inventory and lifecycle only through the effective Persistence-selected management skill, and route delivery through Dev Orchestrator with the effective Commit-selected skill.

For a declared backlog blockage, require resolve-backlog-blockage to own diagnosis and sequential recovery. When a secondary-thread dispatch mechanism exists, require set-solo-mode at entry and set-multitask-mode only after every recovery exit condition passes. Require DISABLED, ALREADY_SOLO, ENABLED, ALREADY_MULTITASK, or NOT_APPLICABLE evidence as appropriate. When no mechanism exists, require recovery to proceed without either dispatch-mode skill. Reject mode skills that diagnose blockage, mutate provider lifecycle, cancel existing secondary work, or launch new work.

Require provider-spanning evidence. File uses backlog paths only through its selected manager. GitHub and GitLab preserve native issue identities and create no shadow files or cross-provider translations. Azure DevOps and Jira preserve their placeholder BLOCKED zero-mutation result. Provider none coordinates only an explicit task with task-local evidence and no inventory or capacity target. UNSET and unavailable selected skills stop at the pertinent boundary without inferred or fallback routing.

For durable inventory, require deterministic evidence that the parent counts lifecycle RUNNING from the selected manager, fills vacancies to ten with eligible READY items, delegates lifecycle mutation to Dev Backlog Steward, stores one canonical task id in each provider record, creates no placeholder or wait-only tasks, and contains ambiguous duplicate dispatches after bounded settlement.

For an answered User Action Required item, require the existing canonical Thread and Agent Task identities to remain distinct and unchanged. With a selected provider, require the Coordinator to decide routing, Dev Backlog Steward to perform each provider mutation, and the same root Dev Orchestrator to accept Running. With provider none, require equivalent task-local evidence with no Steward dispatch, provider mutation, inventory, or capacity inference. Preserve dirty ownership and early artifacts for normal scope, review, verification, and delivery reconciliation; never accept them as delivery or reject them solely because of Thread location.

For delivery, require one Dev Orchestrator to retain its item through independent review, focused tests, and the effective Commit-selected skill. An unavailable Event Contract claim uses one immediate attempt, task-local structured evidence, and a direct release or recovery handoff. Retry only when that notification arrives. Never accept registry polling, time-driven retries, or provider mutation merely to record the wait. Only the watchdog investigates stale ownership on its normal cycle. When a notified retry remains unavailable, require another direct handoff or a truthful disposition at an already-authorized material provider boundary, and fill the active vacancy when durable inventory supports replacement. Reject any attempt to reproduce provider or Commit procedures inside the coordinator.

Do not require claims for implementation, correction, review, generation, or focused local tests confined to a task-owned private worktree. Require project-files only immediately before non-backlog primary-worktree integration, exact current and destination backlog paths only for an existing item update or move, and named resource claims only for the remaining Event Contract triggers. Require Commit READY and selected-provider completion before parent cleanup, except that provider none carries its full terminal result in task-local evidence. Then require the parent to remove the clean worktree, safely delete the merged branch when one existed, set Done, archive the task, and refill durable Running capacity.

Require focused tests for each work item and independent merging after acceptance. When related work items form a combined regression set, require the Coordinator to record the selected items, wait until every selected item is present on main, and run one system-wide regression against that exact main commit. The later regression must not delay individual merges. A distinct failure becomes a defect against the tested main state and does not automatically invalidate unrelated focused evidence.

Run the suite-owned simulator tests before semantic judgment. Require broad-claim and broad-test three-option analysis only as a post-facto improvement after actual waste, never as a gate. Reject any separate task ledger, baton registry, waiting-task chain, title-only identity, ordinary Git approval request, per-item complete-catalog run, provider fallback, or completion claim without selected-Commit and provider evidence.
