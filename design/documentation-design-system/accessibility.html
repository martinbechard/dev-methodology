Concern 07

Accessibility And Responsive Behavior

Accessible documentation keeps structure, names, focus, feedback, and reading order available at every viewport. Responsive changes must preserve the same information and interaction.

Accessible Names And Descriptions

Controls and visuals need names that describe their purpose. Visible labels should provide the name when possible.

  • Brand images use meaningful alternative text.
  • Decorative arrows and gear glyphs use aria-hidden="true".
  • Icon-only controls use aria-label.
  • SVG figures use title and desc.
  • CSS diagrams use role="img" with a text alternative.

Keyboard And Focus

Every interactive component needs a visible focus indicator and a complete keyboard path.

Navigation

Pill links use :focus-visible with a three-pixel outline. Sticky section navigation becomes static on small screens.

Dialog

The settings control moves focus into the dialog, closes on Escape, and returns focus to the trigger.

Disclosure

Native details and summary preserve keyboard behavior.

Workflow

The complete account fixture moves focus to the next heading or completion status.

Responsive Behavior

The audited snapshot at 36f8c1be6d04c865c4e718917c5812dc3fdf0363 uses content-driven breakpoints from 520 to 900 pixels. Common changes reduce padding, stack columns, wrap navigation, and move wide tables into horizontal overflow.

520–560Narrow diagrams, grids, and page-specific structures
620–720Controls, shared shell padding, and editorial layouts
780–900Wide matrices, hero splits, and complex diagrams

Breakpoint values are inconsistent, but several are tied to real component failure points. Later standardization should test components before collapsing them into one global breakpoint.

Print

Print styles remove navigation and controls, use a white background, prevent important cards from splitting, and retain readable content.

Explicit print sources: agent-and-skill-evaluations.html; agent-owned-evaluation-suites.html; orchestrated-development-lifecycle.html; page-section-navigation.css; styled-backlog-report.html.

Observed Accessibility Gaps

The audit found useful patterns that are not applied consistently across the primary documentation suite.

  • Only wiki-skills-and-project-context.html provides a skip link and a target ID on main.
  • orchestrated-development-lifecycle.html does not associate its hero with the page title through aria-labelledby.
  • Some wide tables make the table itself scrollable; a wrapper is more predictable.
  • Only five source surfaces define explicit print behavior.
  • The deliberate accessibility-defects.html fixture contains an unlabeled input and is not a production example.
