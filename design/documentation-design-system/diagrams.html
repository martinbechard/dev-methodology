Diagrams

Diagrams clarify relationships that prose alone makes difficult to scan. Technical SVG diagrams use a separate connector and block-entry arrow so every arrowhead meets a block cleanly.

SVG Block-Entry Connector Standard

A block-entry connector has two elements: a routed connector and a short-stem arrow. The connector stops before the block, and the separate arrow completes the entrance.

Core rule

Do not place marker-end on a connector that enters a block. End the connector at the short stem, then place the reusable arrow on the same centerline.

Reproducible Entrance Geometry

The block boundary determines every entrance coordinate. Authors can calculate the connector end and symbol placement instead of adjusting unexplained coordinates.

Coordinate calculation

Let B be the destination block’s top boundary and C be the entrance centerline.

  1. Set the arrowhead depth to d = 9.
  2. Set the stem length to the same value, d.
  3. End the connector at (C, B - 2d), which is connector end B - 18.
  4. Place the ordinary symbol at x = C - 7 and y = B - 18.
  5. Place the strong symbol at x = C - 14 and the same y coordinate, with the tip at B.

Fan-Out Layout

A fan-out starts at one source and enters several destination blocks. Each route owns one curve and one short-stem arrow.

Choose a source anchor for each branch. Route each Bézier curve directly to (C, B - 18) for its destination. Do not terminate a curve at another branch’s arrowhead.

Fan-In Layout

A fan-in combines several inputs into one destination. Every connector ends at one convergence point, and one strong arrow completes the combined entrance.

The convergence point is the start of the strong stem. The strong symbol keeps the same 9-unit stem and 9-unit arrowhead depth while doubling the shaft and arrowhead width.

Connector Quality And Verification

A technically correct path can still fail visually. Review the final browser rendering at desktop and narrow widths.

Authoring rules

  • Use rounded line caps and smooth Bézier curves.
  • Avoid intersections except at intentional convergence points.
  • Keep arrowheads outside block interiors.
  • Preserve whitespace around labels and connectors.
  • Use consistent color and line weight for related connectors.
  • Keep every connector and arrow on the block entrance centerline.

Rendered checks

  • Check for detached arrowheads and doubled segments.
  • Check for accidental horizontal collector rails.
  • Check for overlapping labels and connectors.
  • Check for clipped arrowheads or blocks.
  • Check for horizontal page overflow.
  • Repeat the checks at desktop and narrow widths.

Do not approve an SVG from source inspection alone. Browser rendering determines whether the stem meets the connector and whether the arrow tip touches the block boundary.

Diagram Semantics

Every meaningful diagram needs an adjacent visible caption and an accessible text equivalent that explains its meaning.

  • Use figure and figcaption for a self-contained visual.
  • Use SVG title and desc for each meaningful SVG.
  • Describe the relationship or process, not only the shapes and colors.
  • Use role="img" and an aria-label for CSS-built visual groups.
  • Keep ordered data in semantic ol markup when the visual is a sequence.
  • Define reusable geometry with symbol and place it with use.
