Persistent context, disciplined authority

Wiki Skills And Project Context

This bundle turns an agent-maintained wiki into durable, compiled project understanding. Distinct roles collect or research raw evidence, ingest or write source-backed topic coverage, verify the result independently, and answer later questions from that maintained context. The wiki accumulates value over time without outranking the code, tests, requirements, procedures, plans, architecture, or backlog records that supply its facts.

Topic ownership follows boundaries: the sections below assign each role, skill, artifact path, verification gate, and federation responsibility one explanatory home.

Four Layers, Not Four Names For One Thing

Pattern

Karpathy LLM-wiki

Places a persistent, agent-maintained Markdown wiki between immutable raw sources and the user. Incremental ingest updates summaries, entity and concept pages, cross-links, contradictions, indexes, and logs. Useful query results can be filed back so future questions begin from accumulated synthesis.

Read the primary LLM-wiki idea file

Representation

Open Knowledge Format

Defines a portable directory of Markdown knowledge documents with YAML frontmatter. Non-reserved concept files need parseable frontmatter and a non-empty type. Normal Markdown links form relationships; index.md and log.md have reserved navigational meanings.

Read the OKF specification

Methodology

Project wiki

Adapts the compounding-wiki idea for repository context. It adds an explicit authority order, standard page sections, source-first ingest, hub and leaf granularity, federation, linting, OKF validation, leaf linking, and independent writer-verifier loops.

Read the project-wiki skill

Specialization

Code project wiki

Adds a commit-aware hybrid for code repositories. Code, tests, specifications, procedures, architecture, plans, and backlog records become synchronization inputs. Wiki pages change only when durable understanding changes; skipped commits or file groups are recorded.

Read the code-project-wiki skill

Compiled Context Flow

The raw-ingest process separates approved public evidence and bounded research reports across three ownership areas.

Raw evidence producers

  • Source Collector captures approved public evidence
  • Researcher records confirmed coverage gaps
→

Wiki Ingester

  • Reads assigned raw or Clippings evidence
  • Synthesizes substantiated leaves, hubs, links, and digests
  • Preserves uncertainty as open questions
  • Runs linking, lint, and OKF checks
→

Independent acceptance

  • Wiki Topic Verifier reviews the changed pages read-only
  • Writer or Ingester owns any correction
  • Verification gates govern acceptance and source movement

Separate query-gap route: the read-only Wiki Query Responder hands missing or stale durable coverage to the Wiki Researcher. The Query Responder does not create a raw fragment or edit the wiki. The Researcher checks local and federated coverage, saves a confirmed gap as a sourced raw report, and leaves that report for the ingest route. Direct use of the project-wiki-query skill may create a raw query fragment when repository mutation is allowed.

Code and tests Specifications and procedures Architecture and plans Commits and backlog

Separate direct-maintenance route: the Wiki Writer updates durable pages from authoritative project evidence outside raw-source ingest. The code-aware specialization classifies repository changes for this route and records changes with no durable context impact as skipped.

Project Wiki Operating Model

Compiled understanding, lower authority

The wiki accelerates orientation and navigation, but source conflicts resolve upward. Actual behavior comes from code and tests; intended behavior, workflow obligations, tracked status, and design intent come from their owning project artifacts. The wiki is corrected from those sources.

Hubs stay small; leaves carry concepts

Folder index pages define a stable domain and route readers. Independently changing frameworks, products, workflows, decisions, governance rules, evaluation questions, and source snapshots become focused leaves. A leaf-link pass connects the first useful mention elsewhere.

Raw and durable paths stay distinct

Raw, raw/processed, and Clippings preserve source evidence and ingest state. docs/wiki holds maintained synthesis. The verification section owns the acceptance rules that separate unprocessed evidence from processed provenance.

Uncertainty remains visible

Conflicts and missing evidence become Open Questions rather than guesses. Lint checks page and link health, OKF validation checks the representation boundary, and bounded independent writer-verifier loops prevent endless self-review.

OKF boundary: this methodology aims for OKF-compatible concept documents; it does not claim that the workflow itself is OKF. The format standardizes exchangeable files. The bundle separately defines source authority, topic sections, ingest, federation, writer ownership, and verification.

Wiki Role Ownership

These roles form an ownership catalog, not one universal sequence. The compiled-context flow above shows the source-backed raw-ingest handoff; direct writing, query response, setup, and methodology review remain separate routes.

Wiki Architect

Establishes or substantially restructures wiki roots, local and federated ownership, source workflows, navigation, automation, and the verification contract after the requester confirms the setup recommendation pack.

Wiki Source Collector

Collects approved public evidence within the requested time window, records dates and exclusions, and hands off a raw-only artifact without changing durable wiki pages.

Wiki Researcher

Checks local and federated coverage first. When a genuine gap remains, it researches only that bounded scope and saves one sourced report under raw for later ingest.

Wiki Ingester

Owns assigned raw inputs, durable synthesis, queue state, source-link corrections, and verifier routing for the ingest path.

In a distinct Project Bootstrapper-assigned whole-project reverse-engineering audit mode, it inspects the complete integrated tree read-only and reports stale, contradictory, or missing evidence to the existing artifact owners.

Wiki Writer

Creates and maintains durable pages, leaves, hubs, links, digests, and code-aware context outside raw-source ingest. It owns all page corrections within that assigned scope.

Wiki Topic Verifier

Independently judges supplied topic pages, leaf coverage, source links, digests, federation boundaries, lint, and OKF status. It returns a verdict and never edits the pages it reviews.

Wiki Query Responder

Answers from docs/wiki first, verifies material claims against authoritative files, and returns a bounded research handoff for missing or stale durable coverage without expanding the read-only query role into research or wiki editing.

Wiki Artifact Reviewer

Reviews project-wiki methodology artifacts in a fresh context for authority, structure, navigation, maintenance rules, automation, and verification completeness using the dedicated checklist and shared page verifier.

Federation Responsibilities

Upstream entity ownership

Broad ecosystem entities, product catalogs, model families, companies, frameworks, protocols, and reusable background stay in the upstream wiki that owns them. Downstream maintainers search the upstream topic index before creating a local entity leaf.

Downstream project context

The downstream wiki owns its project-specific practice, workflow, implementation, evaluation, adoption, governance, and decisions. It links upstream for shared facts instead of building a parallel encyclopedia entry.

Shared and conflicting coverage

A shared concept keeps ecosystem facts upstream and the local decision or operating rule downstream. Missing or conflicting upstream coverage becomes an explicit open question or a narrowly necessary local note, not a silent ownership fork.

Source and feed routing

Downstream feeds do not duplicate public topics already collected upstream. Evidence about an upstream-owned entity is saved as raw material for the appropriate owner or becomes an open question about routing, while downstream feeds stay focused on local sources and local practice.

Recorded boundary: docs/wiki/federation.md names the relationship direction, upstream and downstream roots, owned scopes, lookup rules, and feed boundaries. Federation is one-way unless the requester explicitly approves bidirectional synchronization.

Skill Collaboration Boundaries

01

project-wiki

Owns the shared wiki engine: shape, authority, setup recommendations, source ingest, federation, hub and leaf rules, operations, lint, and OKF validation.

02

project-wiki-create

Creates or substantially rewrites one repository's wiki methodology artifact from the supplied template. Ordinary topic editing stays with project-wiki.

03

project-wiki-query

Answers from docs/wiki first and verifies against authoritative files. When the durable-gap trigger passes, mutation-capable direct use saves a raw query fragment only if mutation is allowed; otherwise it reports the fragment that should be created.

04

project-wiki-research

Checks existing and federated coverage before bounded external research. A genuine gap becomes one sourced raw report for later ingest, not an immediate wiki edit.

05

project-wiki-review

Reviews a project-wiki methodology artifact against its template, source authority, maintenance rules, page contract, and code-aware navigation.

06

project-wiki-topic-write

Owns topic-page edits, leaf splitting, hub and index updates, source links, local validation, corrections, and the verification handoff. The conceptual writer or ingester role owns independent verifier routing and interruption handling.

07

project-wiki-topic-verify

Independently and read-only judges the changed topic pages, leaf coverage, source links, digest and federation boundaries, lint, and OKF validation.

08

code-project-wiki

Adds commit-range classification, repository source synchronization, Related Code and Related Tests upkeep, and explicit skipped-change records to the shared engine.

Code-Aware Hybrid

When it applies

Use code-project-wiki when maintaining docs/wiki for a code repository, inspecting a commit range, changing source ownership, updating verification evidence, or deciding whether recent repository changes alter durable project understanding.

What it reads

Changed code and tests establish actual behavior and verification. Specifications, procedures, architecture, high-level and module designs, plans, and backlog items supply intent, workflow, ownership, decisions, and known gaps.

What it writes

Existing leaves are preferred. New leaves are reserved for concepts that can recur or change independently. Related Code and Related Tests point back to project-relative evidence, and uncertain source disagreements remain open questions.

What it skips

Generated noise, refactors with no ownership or behavior impact, and other changes that do not alter durable understanding do not force a wiki edit. Their commit or file group is recorded as skipped so the sync remains auditable.

Verification Gates

Raw ingest before movement

The Wiki Ingester runs leaf linking, lint, and applicable OKF validation, then obtains a fresh Wiki Topic Verifier verdict for the complete changed-page set. Only GOOD authorizes moving the source to raw/processed.

Processed links after movement

After a source moves, the ingester updates every affected page to the processed relative link, reruns validation, and requests a fresh post-move verdict whenever topic-page links changed.

Direct page maintenance

The Wiki Writer owns corrections and resubmits through the bounded verifier loop. The Wiki Topic Verifier remains read-only, and an interrupted non-verdict never becomes implied acceptance.

Methodology artifacts

Project-wiki methodology artifacts use the Wiki Artifact Reviewer, the project-wiki checklist, and the shared documentation page verifier rather than the topic-page ingest gate.

Compounding Context

Ingest compounds

One accepted source can update several existing leaves, add a focused leaf, refresh indexes, and preserve contradictions as open questions for later work.

Queries compound

Later questions begin from maintained synthesis, verify it against current authority, and expose durable gaps that the bounded research and ingest routes can address.

Health checks compound

Lint and review expose orphan leaves, missing cross-links, oversized hubs, stale claims, unresolved contradictions, and concepts that deserve their own page. Corrections strengthen the shared context for every later agent.
